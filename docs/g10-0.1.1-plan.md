# G10 response-default policy — 0.1.1 maintenance release

## Scope and fixed inputs

Release `scm-sdk 0.1.1` from the published 0.1.0 development line at
`840c0906f57548e6c13c1cd98152ad1ac18732a8`, incorporating the reviewed branch
`g10-no-response-defaults`, commit `a6d63e58f067a98504e5b79987639d53e11fc931`.

0.2.0. It is outside this patch. Preserve the frozen TypeScript 0.34.0 baseline,
all existing operation names and signatures, Rust 1.89 MSRV, and dependencies.

The patch basis is [STABILITY.md, Version policy](STABILITY.md#version-policy):
patch releases stay source compatible, including experimental APIs. Two additive
methods and a variant on an already non-exhaustive enum satisfy that rule when
default behavior, feature/dependency requirements and existing signatures remain
unchanged. The opt-in accounting fix restores the branch's advertised contract.
The vendor expansion's breaking query changes remain assigned to 0.2.0.

The maintainer explicitly authorized review, fixes, merge, push, tag and crates.io
publication of 0.1.1. Keep v0.1.0 and all historical receipts intact. The release
must not claim broader live acceptance than the new source-bound execution proves.

## Compatibility contract

- `Mode` remains non-exhaustive. Add `ResponseWithoutDefaults` and the additive
  `RequestOptions::without_response_defaults(self)` and `response_defaults(&self)`.
  Every newly constructed request option reports `true` by default.
- Without the option, normalization is unchanged, including all 23 frozen default
  bindings. Request validation is unchanged in every mode of response handling.
- With the option, validation accepts and rejects the same documents as
  `Mode::Response` under identical public validation limits. Validate omitted
  defaults and charge their work/copy budgets before suppressing their output.
  Preserve union selection, refinements, unknown fields/vocabularies and explicit
  nulls. Inspect effects and pipeline combinations for acceptance differences.
- Typed Red Team targets `get`, `list`, every `list_all` page, `create`, `update`,
  `probe` and `update_profile` must serialize to the server document exactly:
  missing fields stay absent, explicit nulls survive. Existing static operation
  names (for example `red_team.targets.get`) and transport/retry policy stay intact.
  The option propagates through buffered JSON and contract SSE decoding.
- Report every one of the 23 bindings with public model, field and JSON default.
  Flag product ownership outside Red Team and retain source node identities so
  shared/repeated bindings are distinguishable. Do not conflate distinct bindings
  that share field names or values.
